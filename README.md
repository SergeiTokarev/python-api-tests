# API-автотесты на Python — учебный репозиторий

Цель: научиться писать API-автотесты на pytest **своими руками**, до уровня,
на котором я защищаю свой код на техническом интервью и могу объяснить
любую строку в рабочем проекте.

Полигон — [restful-booker](https://restful-booker.herokuapp.com/apidoc/index.html),
публичный тренировочный API. Домен — бронирования, тот же, что в рабочем
Partner API, поэтому знания переносятся напрямую.

## Правила

1. **Весь код в `tests/` пишу я сам.** Claude объясняет, даёт задания,
   ревьюит и задаёт вопросы — но не пишет тесты за меня. Иначе репозиторий
   получится таким же незащищаемым, как рабочий.
2. **`reference/` — единственный готовый код.** Это учебник, его читаем
   и разбираем. Эндпоинты там намеренно другие, чтобы копипаста не работала.
3. **Сначала руками, потом кодом.** Прежде чем писать тест на поведение —
   проверить это поведение в Postman или curl. Тест на предположение — мусор.
4. **Застрял на 20 минут — спрашиваю.** Застрял на 2 минуты — думаю сам.
5. **Коммит после каждого урока.** История коммитов — доказательство,
   что код писал я, а не сгенерировал за один вечер.

## Запуск

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

pytest                                  # всё
pytest tests/test_lesson_01_get.py      # один файл
pytest -k nonexistent                   # по части имени
pytest -x                               # остановиться на первом падении
```

## План

| # | Тема | Что отрабатываем | Параллель с рабочим проектом |
|---|------|------------------|------------------------------|
| 1 | GET, assert, JSON | `requests`, статусы, разбор тела, внятные сообщения | базовый слой любого теста |
| 2 | Фикстуры | `conftest.py`, scope, переиспользование сессии | `tests/conftest.py` |
| 3 | POST | создание сущности, сверка отправленного с полученным | создание инструктора/класса |
| 4 | Авторизация | токен, негативные кейсы 401/403 | `test_security.py` |
| 5 | PUT и PATCH | полное и частичное обновление, что меняется и что нет | PATCH-тесты ресурсов |
| 6 | DELETE и teardown | `yield`-фикстуры, уборка за собой | `cleanup_entities` |
| 7 | Параметризация | `@pytest.mark.parametrize`, границы, эквивалентные классы | негативные наборы данных |
| 8 | Валидация схем | `jsonschema`, потом `pydantic` | `schemas/`, `utils/models.py` |
| 9 | Рефакторинг в клиент | класс `BookingsAPI`, HTTP отдельно от проверок | `clients/base.py` |
| 10 | CI и отчёты | Allure, GitHub Actions, запуск в Docker | `.gitlab-ci.yml` |

К концу урока 9 рабочий `partner-api-autotests` станет понятен построчно —
он устроен ровно так же.
